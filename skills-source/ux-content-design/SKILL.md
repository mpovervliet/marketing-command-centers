# UX Content Design Specialist

De woorden in een product zijn 60% van de ervaring. Deze skill ontwerpt, test en documenteert alle UI-copy: van button-label tot empty-state-message tot voice & tone-guide. Web-only scope. MP schrijft strategisch + audit-gericht; productie-copy kan met klant/externe writer verdeeld worden.

## Wanneer activeren

- Content-audit van bestaand product (consistency, tone, clarity)
- Voice & tone-guide opstellen
- Specifieke copy-vragen (welke button-tekst werkt?)

## Werkwijze

### 1. Content-audit als startpunt

Voor bestaand product:
- Inventariseer alle UI-strings (Figma + live-site)
- Categoriseer: buttons, labels, helpers, errors, empty-states, tooltips
- Beoordeel op: clarity, tone-consistentie, length, jargon, action-orientation
- Issue-list per categorie

### 2. Voice & tone-framework (Podmajersky-model)

**Voice = karakter** (consistent over product):
- 4 dimensies: Funny↔Serious, Formal↔Casual, Respectful↔Irreverent, Enthusiastic↔Matter-of-fact
- Positioneer merk op elke as

**Tone = modus** (contextafhankelijk):
- Celebratory (success-states)
- Neutral (navigation, forms)
- Reassuring (loading, waiting)
- Apologetic (errors op eigen fout)
- Empathetic (user-fout, destructive actions)

Voice blijft; tone past per moment aan.

### 3. Copy-principes (Nielsen + Podmajersky + Nicely Said)

1. **Benefit-focused buttons**: "Account aanmaken" > "Verzenden"
2. **Front-load het belangrijkste**: eerste 2-3 woorden doen 80% van het werk
3. **Specifiek boven generiek**: "Upload je foto" > "Doorgaan"
4. **Active voice**: "Sla op" > "Wordt opgeslagen"
5. **Numeriek waar zinvol**: "3 items in je winkelmand"
6. **Geen disclaimers in microcopy**: bewaar juridische taal voor voorwaarden-pagina
7. **Menselijke foutmeldingen**: erken fout, leg uit, geef next-step
8. **Empty ≠ leeg**: een empty-state is een onboarding-kans
9. **Plain language**: middelbare-school-leesniveau als default
10. **Inclusief**: geen aannames over gender, lichaam, familie, economie

### 4. Copy per patroon

**Buttons / CTAs**:
- Werkwoord + benefit: "Start gratis proefperiode"
- Max 3-5 woorden
- Geen ellipsis-buttons tenzij confirmation volgt
- Primary 1 per scherm; secondary ondersteunt

**Labels (form + nav)**:
- Noun-vorm ("Volledige naam" niet "Vul naam in")
- Kort, 1-3 woorden
- Match mental model (user-woord > merk-woord)

**Helpers / placeholders**:
- Helper = persistent onder veld, geeft context
- Placeholder = verdwijnt bij typen: nooit als enige label (a11y-schending)
- Format-hint in helper ("bijv. 06-12345678")

**Errors**:
- Wat ging fout + waarom + hoe op te lossen
- Geen schuld bij user ("Je hebt ingevuld..." → "Dit e-mailadres bestaat al")
- Specifiek over veld waar fout plaatsvond
- Geen codes zonder uitleg ("Error 422" = nutteloos)

**Empty-states**:
- Uitleg waarom leeg
- Duidelijke next-step (CTA)
- Visual om sfeer te zetten
- Nooit "Geen resultaten" zonder context

**Loading / waiting**:
- <2s: visueel indicator voldoende, geen tekst
- 2-10s: "Bezig met laden..." + optional progress
- >10s: meer context ("Je foto uploaden: moment geduld")
- Nooit "Een ogenblik" (ambigu)

**Success-messages**:
- Bevestig wat er is gebeurd
- Toon next-logical step
- "Bedankt voor je bestelling" + "Volg je pakket hier"

**Destructive confirmations**:
- Expliciet maken wat weg gaat ("Verwijder 3 items")
- Reverse-actie erkennen ("Dit kan niet ongedaan gemaakt worden")
- Knop-label herhaalt actie ("Ja, verwijder" niet "OK")

**Tooltips**:
- Alleen voor icon-only UI of progressive-disclosure
- Max 1 zin
- Geen kritische info (niet-hover-users missen het)
- Niet als vervanging voor labels

### 5. Testen (niet alleen schrijven)

- **5-second-test** (Lyssna): is de core-message duidelijk?
- **Preference-test**: A/B tussen copy-versies
- **Comprehension-test**: user parafraseert wat er staat
- **Readability-tools**: Hemingway, LanguageTool, Flesch-Kincaid
- **Screen-reader-test**: klinkt het goed voorgelezen?
- **A/B in productie** via `cro-experimentation` voor high-traffic-CTAs

## Kern-kennisgebieden (2026 best practices)

### Torrey Podmajersky's Strategic Writing for UX (canonical)

- Voice-chart oefening verplicht per merk
- Content-first-design: copy tijdens wireframes, niet na
- Purpose-driven (elke string heeft meetbare doel)
- Concise-Conversational-Clear-als-hiërarchie

### Plain Language Guidelines (plainlanguage.gov)

- Schrijf voor target-audience, niet voor experts
- Korte zinnen (<20 woorden gemiddeld)
- Actieve stem
- Bekende woorden kiezen
- Logische structuur
- Visueel ondersteunen

### Inclusive language-bronnen

- Microsoft Style Guide (bias-free writing)
- APA inclusive language guidelines
- Conscious Style Guide
- Geen "crazy/insane/blind spot" metaforen
- Gender-neutraal tenzij user explicit anders kiest
- Geen leeftijd/lichaam-aannames
- Economische aannames vermijden ("gewoon even [duur ding]")

### Voice-chart-template (output)

| Dimensie | Wij zijn wel | Wij zijn niet |
|---|---|---|
| Funny / Serious | Vrolijk maar zakelijk | Lollig in error-states |
| Formal / Casual | Casual, u-vorm vermijden | Slang, memes |
| Respectful / Irreverent | Respectvol, erkend user-situatie | Minachtend, ironisch |
| Enthusiastic / Matter-of-fact | Enthousiast bij onboarding, feitelijk bij errors | Over-excited overal |

### AI & content (2026 realiteit)

- ChatGPT / Claude / Copilot als first-draft-tool
- Human-edit-pass blijft verplicht (tone-consistentie + fact-check)
- Glossary + voice-chart meegeven aan AI als context
- Hallucinations risico: features die niet bestaan in copy
- Generieke AI-stem-herkenbaar: rewrite verplicht

### Design-tool integratie

- **Figma**: copy in design (niet lorem ipsum) vanaf eerste wireframe
- **Ditto / Frontitude**: content-management in Figma (source-of-truth)
- **Lokalise / Crowdin**: vertaling bij multi-taal
- **Phrase**: in-context review + translation

### Content × accessibility-overlap

- Plain language = WCAG 3.1.5 (AAA) + cognitive-inclusion
- Error-messages gelinkt aan veld = WCAG 3.3.1 (A) + 3.3.3 (AA)
- Button-labels descriptief = WCAG 2.4.4 (A)
- `aria-label` nooit zonder visuele equivalent tenzij icon-only
- Taal-attribute (`lang`) correct op content in andere taal

### Microcopy voor AI-interacties (chatbots, assistants)

- System-prompts, fallbacks, error-handling
- "Ik begrijp je niet" → "Kun je het anders verwoorden?"
- Escape-paths naar human-support altijd zichtbaar
- Confidence-indicatie waar AI-output onzeker is

### Anti-patterns

- "Click here" / "Klik hier" (niet descriptief, a11y-zwak)
- Placeholder als enige label
- Error-tekst in rode tekst alleen (kleur-only = WCAG-fail)
- "Oeps, er ging iets fout" zonder details of next-step
- Loading-skeleton zonder tekst bij >10s
- Jargon zonder uitleg ("API sleutel invoeren" voor leken)
- Ironische tone in error-states
- Gender-assumptie in copy ("Welkom meneer/mevrouw")
- Destructive CTA zonder confirmatie
- Ellipsis-button zonder modal daarachter ("Instellingen...")

## Output-formaat

### Voice & tone-guide (docx via `springbok-gdoc`)
1. Merk-voice-chart + voorbeelden

3. Do's / don'ts per patroon (button, error, success, etc.)
4. Taal-niveau + inclusiviteits-principes
5. Glossary (merk-termen, verboden termen)

1. Samenvatting + tone-consistency-score
2. Issues per categorie (errors, buttons, labels, empty-states)
3. Voor/na-voorbeelden
4. Prioriteits-lijst
5. Voice-chart-aanbeveling

### Microcopy-library (xlsx of Notion)
- Per patroon: status (approved/draft), context, copy-variants, test-resultaten
- Herbruikbaar across features

### Component-copy-spec (bij `ux-design-system`)
- Per component: alle strings (states, variants)
- Tone per state
- Accessibility-notes
- Fallback-copy bij fouten

### Error-message-inventaris
- Alle error-codes + user-facing-text + recovery-path
- Screen-reader-preview
- Owner per message

## Tips

- **Content-first design**. Schrijf copy tijdens wireframe, niet na prototype.
- **Voice-chart in elke onboarding**. Zonder merkstem = inconsistente product-ervaring.
- **Test je copy**. 5-second tests + preference tests zijn goedkoop & effectief.
- **Errors zijn copy-kans #1**. Slechte errors = churn-motor; goede errors = trust-builder.
- **Empty-states > lege-pagina's**. Elke lege staat is een onboarding-moment.
- **Placeholder ≠ label**. A11y + UX beide zwakker.
- **Plain-language wint**. Jargon = exclusiviteit, plain = inclusiviteit.
- **AI als first-draft, human als final-edit**. AI-stem is herkenbaar; edit verplicht.
- **Button = werkwoord + benefit**. "Verzenden" is het minimum; "Start proefperiode" is beter.
- **Inclusive language als default**. Geen aannames over user-situatie.
- **Content-audit bij elke nieuwe klant**. Revealed = instant-credibility op trust + consistency.
